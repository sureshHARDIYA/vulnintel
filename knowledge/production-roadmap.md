# Production readiness: implementation plan

VulnIntel's current crates provide initial HTTP queries, basic normalization primitives, conservative exact-ID deduplication, OSV response matching and OWASP ASVS parsing. This does **not** mean an end-to-end security scanner is implemented.

## P0 — correct vulnerability correlation
- Versioned normalized advisory schema, immutable provenance per upstream assertion, canonical identity graph with alias conflict detection and withdrawal handling.
- CycloneDX and SPDX SBOM parsers; package-url (PURL) normalization; ecosystem-specific version/range matching; CPE matching only when there is sufficient evidence.
- Correct affected/not affected/unknown semantics, test fixtures for semver, Maven, Python, Go, Debian, RPM, Rust and NPM edge cases; avoid treating empty feed results as proof of safety.
- KEV and EPSS joins by CVE, retain EPSS observation date and evidence timestamps. Reject stale joins.
- Reproducible integration tests with recorded upstream fixtures, malformed payloads, duplicate aliases, withdrawal and conflicting severities.

## P1 — durable, resilient ingestion
- Dedicated ingestion runner with explicit rate limits per provider, 429 Retry-After, conditional GET, exponential backoff with jitter, timeouts, circuit breaking and a bounded work queue.
- Provider-specific incremental pagination / updated-since watermarks, replay and backfill. OSV is package-query first; do not mischaracterize it as a global recent-CVE list.
- SQLite for local single-node usage with transactional schema migrations and unique keys; optional PostgreSQL adapter for distributed deployments. Persist raw source records, normalized statements, checkpoints, failures and provenance.
- Data quality dashboards, ingestion latency and freshness SLOs; structured tracing with sensitive data redaction.
- Offline replay and recovery documentation; observability exporters optional so the core crate remains lightweight.

## P2 — standards / ecosystem depth
- OWASP ASVS 5.0 version-pinned parsing (initial CSV parser exists); traceable mapping to evidence, but not automatically claimed compliance.
- Direct CVE List v5 feed, ENISA EUVD, vendor CSAF/VEX, CWE and CAPEC classification where redistribution and update terms permit.
- Maintain provenance and deduplicate republished advisories; review RustSec, GitLab, OSV overlap before adding sources.
- Public read-only static site with source / update timestamps, filters, error state, downloads and explicit completeness limitations.

## Security release gates
- All tests / clippy / fmt / package and dependency audits pass.
- Independent validation against known affected + unaffected fixture sets.
- Performance and failure tests for pagination and intermittent upstream failures.
- No autonomous remediation; no assertion of application exposure without inventory evidence.
- Publish crates only on explicitly published stable GitHub Releases; main branch pushes never publish crates.

## Public Pages scope
GitHub Pages is a public read-only **snapshot**, not a hosted scanner or application inventory service. Data is generated by a scheduled GitHub Action from public GitHub Advisories and CISA KEV and served statically. It does not need tokens from site visitors. The page never exposes private SBOMs or projects.
